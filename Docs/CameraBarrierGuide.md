# 镜头挡墙 BP_CameraBarrier：地编使用教程

更新时间：2026-11-05。面向地图设计师。程序实现与原理见 [RoomViewHandover.md](RoomViewHandover.md)。

## 1. 它是做什么的

镜头挡墙放在一个区域**最左侧或最右侧的墙**上，作用是：**玩家在这个房间里时，画面上看不到墙后面（下一个场景）的内容。**

例如住宅最右侧的玄关外面是楼道。在玄关的右墙放一面挡墙后：

- 玩家用鼠标或右摇杆往右推镜头，推到墙边就推不动了。
- 玩家自己走到玄关墙边，镜头会在墙边停住，不再跟着往右走。玩家会走向画面右边缘。
- 玩家走进门、暂时走出画面是正常的。等玩家脚下进入楼道的区域，镜头会用大约 0.6 秒平滑地移进楼道，把玩家带回画面中。
- 看不到的范围按画面边缘计算，并且会照顾到房间最深处。换成 21:9 等更宽的屏幕也不会穿帮。

挡墙只影响镜头，没有碰撞，不挡玩家，也不影响交互和声音。

## 2. 放之前要准备好什么

挡墙依赖房间区域（`BP_RoomRegion`）来判断玩家在哪个房间。

1. 墙两侧的房间都要各放一个 `BP_RoomRegion`，并填好 `RoomId`，例如 `Home.Living` 和 `Building.Corridor`。
2. 区域盒子要罩住玩家站立的地面。判定看的是**角色脚下的位置**。
3. 门洞处的两个区域盒子可以稍微重叠。站在重叠的地方，系统会保持玩家原来所在的区域，所以不会来回闪。

区域的详细配置见 RoomViewHandover.md 第 3 节。

## 3. 放置步骤

以“住宅玄关右墙，挡住门外楼道”为例：

1. 在内容浏览器打开 `/Game/Blueprints/RoomView/`，把 **BP_CameraBarrier** 拖进关卡。不要直接拖 C++ 类 `Camera Barrier`。
2. **调整方向**：旋转挡墙，让红色箭头**指向要保护的房间**。这个例子里玄关在左、楼道在右，所以箭头指向左边（住宅里面）。
3. **摆放位置**：挡墙的红色盒子有一面背对箭头，这一面就是边界线，画面最多只能看到这里。把这一面对齐到墙的**外表面**（靠楼道的那一面）。这样墙本身和墙的断面还能出现在画面里，墙后面的东西就看不到了。
4. **调整大小**（Box Extent，或者用缩放）：
   - **厚度方向（X，箭头方向）**：薄一点就行，比如 10。
   - **深度方向（Y）**：要盖住房间的整个深度，从最靠近镜头的位置一直到房间的后墙。**深度不够时，远处还是会穿帮。** 宁可大一点。
   - **高度方向（Z）**：从地板盖到天花板。
5. **填写所属区域**：在 Details → Camera Barrier → `Active In Room Ids` 里点 +，填这面墙所在房间的 `RoomId`，这个例子填 `Home.Living`。要和 `BP_RoomRegion` 上的 `RoomId` 完全一致。
6. 保存关卡，运行 PIE 检查（见第 6 节）。

## 4. 参数说明

| 参数 | 默认值 | 说明 |
|---|---|---|
| Active In Room Ids | 空 | 玩家在这些区域里时，挡墙才生效。通常填墙所在房间自己的 RoomId。**留空表示一直生效**，包括玩家不在任何区域时。一般不建议留空 |
| Safety Margin Cm | 10 | 画面边缘离边界线至少再留多少厘米。觉得墙外还能看到一点点时就调大 |
| Barrier Enabled | 勾选 | 取消勾选后挡墙不起作用，可以用来临时对比效果 |
| Barrier Box（盒子） | 10 × 400 × 250 | 见第 3 节第 4 步。盒子没有碰撞，游戏中不显示 |

## 5. 常见摆法

**一个房间两头都有门。** 左墙、右墙各放一面，箭头都指向房间里面，`Active In Room Ids` 都填这个房间。

**两个相邻房间都要防穿帮。** 同一面墙两侧各放一面挡墙：

| 挡墙 | 箭头方向 | Active In Room Ids |
|---|---|---|
| 玄关一侧 | 指向住宅 | `Home.Living` |
| 楼道一侧 | 指向楼道 | `Building.Corridor` |

玩家从住宅走进楼道时，住宅那面会慢慢失效，楼道那面会慢慢生效，镜头从一边平滑过渡到另一边。

**过渡时会扫过上一个房间。** 镜头移进新房间时，画面会短暂扫过旧房间。如果不想让玩家看到旧房间的内容，可以在新房间的 `BP_RoomRegion` 的 `Blackout Room Ids` 里填上旧房间的 RoomId。玩家一进新房间，旧房间就会变成黑场。

**房间比画面还窄。** 左右两面挡墙不可能同时满足时，镜头会停在两面墙中间不动，不会来回抖。剩下能看到的部分建议用黑场处理。

**玩家在门里出画的时间。** 玩家出画的时长，取决于门有多厚，以及两个区域盒子在门口的分界位置。分界越靠近新房间，出画的时间越长。

## 6. 检查清单（PIE）

- [ ] 在房间里用鼠标或右摇杆往墙那边推到底：看不到墙后的任何东西。
- [ ] 贴着墙走到门口：镜头在墙边停住，期间看不到下一个房间。
- [ ] 穿过门：玩家可以短暂出画，进入新房间后镜头平滑跟上，不卡住、不瞬移。
- [ ] 在门槛上来回走：镜头不来回抖。
- [ ] 改成 21:9 或更宽的分辨率再试一次：仍然不穿帮。
- [ ] 往回推镜头（远离墙）：马上就有反应。

## 7. 常见问题

| 现象 | 原因和解决办法 |
|---|---|
| 挡墙完全没效果 | `Active In Room Ids` 拼写和区域的 RoomId 不一致；玩家脚下不在那个区域里；`Barrier Enabled` 没勾选；箭头方向反了 |
| 镜头离墙很远就停住 | 箭头方向反了，或者盒子的深度（Y）拉得远超房间。检查方向，深度盖住房间就行 |
| 远处角落还能看到墙后 | 盒子的深度（Y）或高度（Z）不够，没盖住房间最深处；或者调大 Safety Margin Cm |
| 镜头上下也被推开 | 盒子转歪了，或者用的不是竖直的墙面。挡墙应该竖直摆放，箭头保持水平 |
| 过门时镜头一下子跳过去 | 新房间的区域没有配 Camera Profile，或者 Profile 里的 BlendSeconds 是 0。BlendSeconds 默认 0.6 秒 |
| 进门后镜头卡在原地 | 新房间没有 `BP_RoomRegion`，或者盒子没罩住门后的地面，所以玩家还被当成在旧房间里 |

## 8. 注意

- 关卡里只放 **BP_CameraBarrier**，不要放 C++ 类。
- 挡墙放在哪里由地图设计师决定。程序只维护功能本身。
- 过场镜头以后可能会临时关闭挡墙，这由程序处理，地编不需要特别设置。
