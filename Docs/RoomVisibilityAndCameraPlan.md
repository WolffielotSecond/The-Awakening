# 房间显隐、动态镜头与墙体切除：实现规划

更新时间：2026-10-30。

**当前实现以 [RoomViewHandover.md](RoomViewHandover.md) 为准。** 阶段 A 的区域镜头逻辑保留。阶段 B 已于 2026-10-30 修订为显式黑场规则：

- `BP_RoomRegion` 保留 RoomId、Priority、CameraProfile。
- 原 DetailActors 重命名为 Included Assets，登记房间包含的 Actor；PropertyRedirect 保留旧引用。
- 当前区域的 BlackoutRoomIds 指定哪些房间的 Included Assets 黑场，Blackout Actors 指定额外黑场 Actor。
- 黑场目标取并集，按组件去重保存 / 还原渲染状态；没有区域或两个列表为空时，不施加黑场。
- 不限制正常显示的房间数量；不自动对称、不递归。Portal 的门口预览规则已取消，旧类和资产仅作停用兼容壳。
- 现有黑场材质和 Stencil 3 机制复用，碰撞、交互和 Tick 不变。镜头仍按角色脚下位置和区域 Priority 选择 Profile。
- 本次不自动给现有地图推断黑场关系；需要在实例上填写新数组。

**以下第 1 节起是历史需求与长期规划存档，并非当前功能清单。** 其中“当前房间 + 门口两侧”的可见集合、PortalId / 有向穿越、门开关控制等旧提案已被上面的显式规则取代，不应照旧实现。后续墙体材质切除、交互过滤、关卡卸载等仍是独立待办，不能当作已交付能力。最新配置步骤、限制与验证状态见交接说明。

## 1. 用户要的最终效果

游戏是固定观察方向为主的第三人称／横向构图场景。角色通过门、走廊与房间移动时，镜头距离、观察范围和可见空间都应随所在位置改变。

### 1.1 动态镜头

- Camera Boom 长度可以按卧室、客厅、住宅走廊、公寓楼道和室外动态调整。
- 鼠标和手柄右摇杆仍可移动观察位置，但不同区域有不同的偏移范围；左右、上下可以不对称。
- 小房间里拉近，室外拉远。切换应平滑，不能频繁抽动，也不能让旧的大范围偏移瞬间带入小房间。
- 公寓楼道里，往家里方向移动鼠标／摇杆不能把镜头探进住宅看内部，更不能穿到墙后看见模型背面。
- 用户主动关闭了 Boom 的 collision test。不要直接重新开启整套自动碰撞回缩，把需求变成普通第三人称缩杆镜头。
- RS 指右摇杆轴；R3 是摇杆按下。镜头偏移应继续使用既有 Look 输入，不把 R3 按钮另做成移动轴。

### 1.2 房间显示

- 玩家站在连接卧室群、厕所与客厅的走廊，姐姐房间应黑掉，不显示其中家具等细节。
- 玩家到姐姐房门口，姐姐房间才允许出现；玩家进入后正常显示。
- 玩家在爸妈房间里，妹妹房间保持黑场；不能因为镜头看到它的方向就自动显示。
- 玩家在住宅里时，室外不应该完整显示。不是当前允许观察范围的空间应为黑色，可保留不抢眼的轮廓／暗影。
- 不开放的房间不能作为一大块黑墙遮住玩家当前所在走廊。它既要隐藏室内细节，也不能挡住当前空间的可读性。

### 1.3 墙体与过门

- 角色与相机之间挡视线的指定墙段可被遮罩切除或渐隐。
- 墙体视觉消失不等于物理消失。角色不能因此穿墙，门锁和交互阻挡仍有效。
- 刚穿过家门时，可以是左侧住宅黑掉、右侧楼道显示的构图。
- **住宅离家关门后就可卸载，本次序章不再返回住宅。** 回程开这扇门进入第一章医院。
- 家门、门框、楼道地面和住宅方向的黑场封口必须能在住宅卸载后继续存在。

## 2. 先分清四个不同概念

| 概念 | 解决的问题 | 不应承担的职责 |
|---|---|---|
| Camera Profile／视图约束 | 站在哪里，用多远的镜头、允许看多大范围 | 不决定剧情进度，不靠鼠标解锁房间 |
| Room Visibility／房间显隐 | 哪个房间的细节允许显示，其他区域如何黑场化 | 不销毁交互 Actor，不替代 Level Streaming |
| Occluder Cutaway／遮挡切除 | 哪些前景墙正在挡住当前角色或观察重点 | 不关角色碰撞，不把黑场房间恢复成正常可见 |
| Level Streaming | 整个住宅／室外版本／医院资源的加载与卸载 | 不用于每次穿过卧室门口时反复销毁与加载房间 |

**黑色、透明、隐藏和卸载不是同一个状态。** 把家具设为不可见，不会自动生成黑色背景；把墙的 Opacity Mask 设为 0，会露出后面的东西，也不会自动把隔壁房间变成黑色。隐藏一个 Actor 也不意味着它停止 Tick、停止逻辑或释放内存。

建议第一版：整套住宅仍在一个 Home 子关卡内；房间级表现用视觉组件／材质处理。只有离家关门等大阶段才卸载住宅。

## 3. 已检查的现有实现

### 3.1 相机与输入

源码入口：

- [The_AwakeningCharacter.h](../Source/The_Awakening/The_AwakeningCharacter.h)
- [The_AwakeningCharacter.cpp](../Source/The_Awakening/The_AwakeningCharacter.cpp)
- [TAFreezeExemptSpringArm.h](../Source/The_Awakening/Core/TAFreezeExemptSpringArm.h)
- [TAFreezeExemptSpringArm.cpp](../Source/The_Awakening/Core/TAFreezeExemptSpringArm.cpp)

当前 Character 构造 `UTAFreezeExemptSpringArm`，组件名为 `CameraBoom`；`FollowCamera` 挂在 Spring Arm socket 下：

- `bDoCollisionTest = false`。
- Boom 不继承 Pawn Control Rotation，也不继承父级 Pitch／Yaw／Roll。
- 启用 Camera Lag，构造默认速度 8。
- BeginPlay 把 `CameraDistance` 写到 `TargetArmLength`，把高度偏移写到 `SocketOffset`。
- 相机俯仰角由 `FollowCamera` 的相对旋转配置。不能只看 Boom 的旋转就推断最终屏幕方向。

现有输入链为：

```text
Look / MouseLook
  -> SubmitPlayerLook
  -> 验证 ETAInputCapability::Look
  -> 应用设备灵敏度与反转设置
  -> DoLook
  -> CurrentCameraOffset
  -> CameraBoom.TargetOffset
```

`DoLook` 当前把左右输入累计到 `CurrentCameraOffset.Y`，上下累计到 `.Z`，用 `CameraOffsetLimitX/Z` 限位，并带已有的软限位曲线。因此变量名里的 X 不代表当前实际写入世界 X。

这里有一个必须验证的坐标问题：**世界轴、Boom 轴、屏幕左右方向不一定一致。** 接手者先确认当前真实画面和 Blueprint 设置，再决定新偏移基底。不要顺手改成自由 Yaw/Pitch 旋转，也不要在房间系统里重复读取鼠标或手柄。

当前 C++ 默认相机距离是 600 cm，但前次编辑器检查实际 `BP_ThirdPersonCharacter` 为 750 cm；实际蓝图胶囊半径为 35 cm、半高为 90 cm。实施前重新核对实际值，不能把构造函数默认值当作运行时事实。

### 3.2 冻结与自动对焦

- `UTAFreezeExemptSpringArm::TickComponent` 使用 World Delta，避免角色扫描冻结后镜头 Lag 也被角色时间缩放锁死。
- `SkipLagOnce()` 用于传送／复活时跳过一次 Lag，避免镜头从旧地点飞到新地点。
- `UTAAutoFocusCameraComponent::GetCameraView` 先取得真实输出视图，再用 `DesiredView.Location/Rotation` 对角色 `FocusPoint` 做光轴投影，最后只覆盖输出视图的焦距。
- 自动对焦不应被新系统改成到墙面或黑场遮罩的距离，也不应覆盖手工光圈、后处理 Blend Weight 等设置。

相关文档：[CameraAutoFocus.md](CameraAutoFocus.md)、[InputRouting.md](InputRouting.md)、[TimeSystem.md](TimeSystem.md)、[ScanFreeze.md](ScanFreeze.md)。

### 3.3 交互、提示和流送

- 交互执行与世界提示共用 `FTAInteractionQuery::FindBestInteractable`；不要只隐藏提示却仍允许穿墙执行同一个交互。
- WorldItem 由 NearbyPickup 路径处理，不能只过滤普通 Interactable，漏掉隔壁房间拾取列表。
- 扫描有自己的候选、Hover 与 CustomDepth 表现，不能假设把主渲染隐藏后扫描就一定看不到。
- 房间显示权不是剧情完成记录，不应创建第二套 StoryStateSubsystem。

参考：[InteractionPrompts.md](InteractionPrompts.md)、[NearbyPickup.md](NearbyPickup.md)、[WorldInteractionSystem.md](WorldInteractionSystem.md)、[SaveSystem.md](SaveSystem.md)、[HealthAndRespawn.md](HealthAndRespawn.md)。

## 4. 推荐的职责划分

以下为待实现的逻辑职责。类型可以合并以控制复杂度，不要求每个名词都做一个 UObject。

### 4.1 空间定义：Room Region 与 Portal

建议新增 `ATARoomRegion`：

- 稳定 `RoomId`，例如 `Home.Hall`、`Home.ProtagonistBedroom`、`Home.ParentsBedroom`、`Entrance.Corridor`。
- 一个或多个空间体积，支持不规则房间由多个 Box 拼接。
- `Priority`，用于房间体积、门口体积重叠时稳定决策。
- `CameraProfile` 软引用或配置引用。
- 正常室内渲染组件集合、黑场代理组件集合、可切除墙集合。
- 与本房间连接的 Portal 列表。
- 初始黑场策略、过渡时长、是否允许门口预览。

建议新增 `ATARoomPortal`，或在现有门 Actor 上挂可复用组件：

- `PortalId`、`RoomAId`、`RoomBId`。
- 门洞平面、A→B 法线、有效门洞宽高。
- 门口预览范围、两侧进入／离开阈值、Portal 优先级。
- 门是否关闭、是否允许观察另一侧的查询接口。
- 可选的过门 Camera Profile／观察锚点。

门口预览不等于把所有相邻房间一起显示。当前站在走廊时最多开放指定门口连接的一间房；有多扇门候选时按优先级、合法门洞和距离稳定选择。

### 4.2 本地玩家视图协调

建议新增 `UTARoomViewComponent` 或同等职责组件，挂玩家／现有镜头管理对象：

- 解析玩家当前 RoomId 和 Portal 过渡状态。
- 维护当前可显示房间集合及权重。
- 选择并混合镜头 Profile。
- 计算允许的观察偏移和安全视图。
- 提供本帧最终视图数据给遮挡控制与自动对焦。

这是本地玩家的视图状态。不要用一个全球 MPC 的单一 CurrentRoomId 假定所有 View 共用同一房间，污染文档预览台、SceneCapture 或以后可能出现的其他本地视图。第一版只支持当前单本地玩家，但职责仍应保持清楚。

### 4.3 视觉注册与遮挡控制

可用 `UTARoomVisualComponent` 登记一个 Actor／组件组的归属；可切除物使用 `UTACameraOccluderComponent` 或数据标签登记。

- Region 负责配置所属关系。
- View 负责给出“当前应该显示哪些区域”。
- Visual 控制最终可见性、黑场代理、材质参数与必要的阴影策略。
- Occluder 负责根据最终视图维护切除对象集合。

单个小住宅无需一开始就增加多个 WorldSubsystem。只有跨子关卡注册确实需要时，才使用一个轻量 World registry；注册与注销按 BeginPlay／EndPlay 成对处理，缓存使用弱引用。

## 5. 数据结构建议

下面是字段草案，不是已经可编译的项目 API。

### 5.1 Camera Profile

`UTARoomCameraProfile : UDataAsset` 可配置：

| 字段 | 用途 |
|---|---|
| ArmLengthCm | 本区目标 Boom 长度 |
| HeightOffsetCm、CompositionOffset | 高度与默认构图偏置 |
| LookLeft/Right/Up/DownCm | 四向独立偏移限位 |
| PositionBlendSeconds、DistanceBlendSeconds | 构图／距离过渡时间 |
| FollowLagSpeed | 继承／覆盖既有跟随 Lag 的策略 |
| LookResponseScale | 区域内偏移响应倍率；不覆盖玩家的设备灵敏度设置 |
| SoftLimitStartRatio | 软边界开始位置，先兼容现有曲线 |
| ViewBounds | 允许的观察中心／最终相机修正范围 |
| MinFocusDistanceCm | 防止约束把镜头推到角色身上 |
| DefaultFOV／是否覆盖 | 第一版默认不改 FOV |
| CutawayPolicy | 本区允许哪些墙体切除、切孔范围等 |

初始调试参考，均非最终验收参数：

| 区域 | Boom 长度 | 左右偏移 |
|---|---:|---:|
| 小卧室 | 350–450 cm | ±30–50 cm |
| 客厅／餐厅 | 450–550 cm | ±60–90 cm |
| 住宅走廊 | 350–450 cm | ±20–40 cm |
| 公寓楼道 | 400–500 cm | 向住宅方向更小，可左右不对称 |
| 室外 | 650–800 cm | 更大范围；追逐时可有前向构图偏置 |

这些范围还要与当前房间实际尺寸、屏幕宽高比、角色在画面中的占比一起调。不要为了容纳旧的 750 cm 镜头再次放大所有卧室家具。

### 5.2 房间与墙体视觉参数

建议统一概念：

- `RoomReveal`：0 为本区细节不可见，1 为正常显示。
- `Cutaway`：0 为该墙不切除，1 为遮挡部位完全切除。
- `BlackProxyWeight`：黑场代理的过渡权重。
- `RoomVisibilityPolicy`：当前房间、门口预览、黑场三种策略，不用 ActorHidden 一个 bool 表示所有含义。
- `ShadowPolicy`：不保留、简化代理、明确允许的隐藏阴影。
- `ScanRevealPolicy`：普通遮挡墙切除与剧情未开放空间分别处理。

共享墙可登记到两个房间，但由一个视觉控制者输出最终结果，避免两个房间轮流改同一个材质。边界门、门框、地板及切换安全地面单独登记，不跟随房间家具一键隐藏。

## 6. 房间判定与门口预览

### 6.1 玩家位置是判定基础

推荐使用胶囊底部附近的稳定位置或角色导航位置。不要使用相机位置来决定 ActiveRoom，否则鼠标探看本身就会解锁房间。

优先规则建议：

1. 活动过场／死亡／过门事务有显式覆盖时，先遵循它的视图上下文。
2. 正在穿越的 Portal 状态。
3. 当前包含玩家的 Region，按 Priority 决策。
4. 同优先级优先保留上一帧合法 Region，再按稳定 ID 打破平局。
5. 无区域时用默认 Profile 和明确 fallback；不能把所有房间当成可见。

不能只依赖 BeginOverlap／EndOverlap。启动、传送、读档后、子关卡刚显示、组件重新注册时，都需要主动按当前位置重新解析一次。

### 6.2 门槛判定

可用 Portal 有向平面判断角色在哪一侧：

```text
signedDistance = Dot(PlayerProbe - PortalOrigin, PortalNormalAtoB)
```

但还要检查门洞横向／高度范围。仅离某个无限平面很近不代表站在门口。

进入和离开阈值分开，例如门口预览距离与退出距离不同，并在真正跨门时使用两侧缓冲。具体数值应按当前 70 cm 胶囊宽度实测，不预设一个硬编码全项目通用距离。

门关闭时默认不开放另一侧预览；若剧情明确允许看玻璃窗、开门缝或某个恐怖线索，通过该 Portal 的配置例外处理。

### 6.3 显示集合示例

| 玩家位置 | 正常显示 | 允许预览 | 黑场 |
|---|---|---|---|
| 卧室群连接走廊中央 | 该走廊与本区必要结构 | 无 | 姐姐、妹妹、爸妈房间与室外 |
| 姐姐房门口 | 当前走廊 | 姐姐房间 | 其余卧室与室外 |
| 姐姐房内 | 姐姐房间 | 仅门口必要的走廊过渡 | 其余房间 |
| 爸妈房内 | 爸妈房间 | 该门口过渡 | 妹妹房间、姐姐房间等 |
| 公寓楼道 | 公寓楼道、门框、必要入口 | 由剧情明确允许的区域 | 住宅内部与非当前区域 |

走廊是否包含客厅、餐厅，取决于它们是否确实是没有遮隔的一个开放空间。不要根据 Outliner 文件夹名机械切黑；先由设计师画清空间区域。

## 7. 动态镜头如何接到现有代码

### 7.1 保留输入入口，只替换后段求解

继续使用 `Look/MouseLook -> SubmitPlayerLook` 的设备设置、输入权限与扫描手柄防重复逻辑。新组件消费已经授权的观察意图，不注册第二套 IMC，不在 Tick 里直接读硬编码键。

`DoLook` 后段从直接写 Boom 改为提交给统一镜头求解器。只有一个位置最终写 `TargetOffset/SocketOffset/TargetArmLength`，否则角色 Tick 和新组件会互相覆盖。

保留对现有 Blueprint 派生和 DoLook 覆盖的兼容检查。缺少 Region／Profile 时继续使用旧参数，已有室外测试地图不应因此变黑或失去镜头控制。

### 7.2 偏移基底与归一化

新实现应明确区分：

- 玩家持续观察意图，最好保存为归一化左右／上下量。
- 区域允许的最大位移，单位 cm。
- 当前混合后的实际观察偏移。
- 最终相机位置。

如果从旧的大范围切换到小范围，先把旧偏移转换／限制到新空间，再平滑过渡，不要让原来的 200 cm 偏移继续作用几秒。

屏幕空间偏移可以由稳定的参考镜头基底转换到世界：

```text
WorldLookOffset = ReferenceCameraRight * HorizontalCm
                + ReferenceCameraUp * VerticalCm
```

参考基底不能从“已经被当前偏移影响的结果”反复反馈计算。当前游戏是固定视角，第一阶段可以保留既有视角，仅验证和整理轴映射；不要连带重写角色朝向、移动方向或 Sprite 朝向。

### 7.3 推荐求解顺序

```text
解析角色空间和 Portal
  -> 选择目标 Camera Profile
  -> 混合距离／高度／构图范围
  -> 应用授权的 Look 意图及软限位
  -> 约束期望观察中心
  -> 更新 Boom 并执行既有 Lag
  -> 形成实际 DesiredView，包含相机附加偏移
  -> 对最终输出视图再做安全约束
  -> 用这个最终视图计算墙体遮挡
  -> 用这个最终视图计算角色自动对焦
```

关键点：距离与构图参数必须在 Boom 本帧求解前准备；最终位置修正必须在自动对焦计算前完成。遮挡查询不能用上一帧相机位置，也不能只用 Boom 之前的期望位置。

可考虑在既有 `UTAFreezeExemptSpringArm` 更新入口前准备 Profile；在 `UTAAutoFocusCameraComponent::GetCameraView` 内，Super 之后、原自动对焦之前调用项目的最终视图修正。具体采用组件先决 Tick 还是直接调用，由实现者验证 UE 5.8 执行次序；不能让普通 Character Tick 成为扫描冻结时唯一更新点。

如果只修正 `DesiredView` 而没有移动组件本体，遮挡服务必须读取最终 `DesiredView.Location/Rotation`，不能又退回 `FollowCamera->GetComponentLocation()`。每个真正游戏视图只求解一次；文档预览相机和 SceneCapture 不应触发玩家房间判定。

### 7.4 禁止探看与物理防穿帮

第一层是观察中心和偏移限位，公寓楼道向住宅方向可接近零；第二层是最终视图约束，覆盖 Lag 与附加位移造成的越界。

固定侧视镜头可能为了剖切构图位于建筑物理外侧，因此**不能要求相机必须待在角色 Room Volume 里**。应单独定义 Camera Safe Bounds／视图平面范围；它们与“角色属于哪个房间”的体积不同。

有必要时，对标记为 Hard Camera Blocker 的对象做专用 Sweep／安全检测；可切除的前景墙不触发整根 Boom 回缩。若候选视图无法满足安全条件，采用最近合法视图或区域预设安全锚点，不把镜头一路挤到角色头里。

有限几个采样点不能证明整个视锥都合法。门洞、近裁剪面、极端宽高比仍需实际画面验收，房间黑场策略也是防止探看的第二道约束。

## 8. 黑场房间如何实现

### 8.1 推荐第一版：隐藏细节＋简化黑场代理

每间房至少区分：

1. **Detail Visuals**：家具、室内装饰、该房间的视觉特效等。
2. **Blackout Proxy**：表达未开放房间 footprint／轮廓的简化黑色几何。
3. **Shared Structure**：门框、共享地板、与当前走廊有关的边界。

非当前房间把细节从正常主渲染中移除，显示黑场代理；门口预览时交叉过渡；进入后显示正常细节。黑场代理通常用稳定的 Unlit 黑色材质作为起点，不依赖把灯关掉后“应该就黑了”。

不要制作一个从地板到天花板完全封死的大黑盒，然后让它挡在镜头与走廊角色之间。黑场代理也要允许与当前角色视线通道相交的部分被切除，或者采用适合固定镜头的剖切面／轮廓结构。切除后露出的应该是当前合法空间，而不是隔壁家具。

隐藏详细 Mesh 后，如果确实需要暗影，优先用廉价轮廓代理。若保留真实隐藏投影，应只对明确需要的组件配置并测试成本；不能给所有家具默认开启隐藏投影。

### 8.2 黑色的最终画面需要验证

Unlit 黑色仍要结合本项目的雾、后处理、曝光和反射验证，不能承诺给 Base Color 写 0 就在所有画面里都是纯黑。

若最终要求严格、稳定的纯黑轮廓，可以增加限定于黑场代理的 CustomDepth／Stencil 与后处理颜色覆盖，但这是第二阶段增强：

- 单纯 Stencil 只能标记有几何覆盖的像素，不能给已隐藏家具留下的空白自动补黑，因此代理仍需要存在。
- 不允许使用全屏固定矩形遮罩跟着角色走，误盖当前空间和角色。
- 与扫描现有 stencil 编号／高亮路径协调，不直接占用已有编号；先调查再分配。
- 纯黑替换的执行位置与 UI／其他后处理先后关系需要在实际渲染路径验证。

### 8.3 隐藏内容的行为边界

- 不 Destroy 房间中的日记、文档、机关或剧情触发器。
- 不因房间黑掉就重置一次性事件、剧情旗标或开门状态。
- 不因 RoomReveal=0 统一关闭 Actor Tick；怪物／剧情／声音可能仍需运行。
- 不直接关闭碰撞，尤其地板、墙和门的物理边界。
- 区域灯光、粒子、Decal、Widget 和 CustomDepth 要分别考虑，避免家具隐藏后还留下灯光或扫描轮廓泄露。
- 门后滴声等剧情音频不能被“非当前房间不显示”一并停掉；视觉规则与声音传播／剧情音频状态分开。

## 9. 墙体遮挡与材质切除

### 9.1 候选对象先登记

只处理显式登记为 Camera Occluder 的墙段、柱子和前景装饰。不要每帧 GetAllActors 再对所有 Mesh 换材质。

候选对象可来自当前 Region、当前 Portal 的两侧和邻近边界的注册表。地板、重要门体、交互机关、角色与 UI 预览台默认排除。共享墙用组件粒度登记，不要求隐藏整个 Actor。

### 9.2 使用最终视图检测

从最终相机位置向角色胸口／头部／必要的构图重点做多点 Line／Sphere Trace，或检测角色包围范围与遮挡几何。单根到脚底的射线会漏掉上半身遮挡和门框边缘。

采用专用查询通道或清晰的过滤策略。为相机检测增加阻挡响应时，不改 Pawn 的通行规则，也不全局改变交互的 Visibility 通道。角色／自身附件、预览模型等应忽略。

切除集合建议每次更新按集合差分维护：

- 新增遮挡：向目标切除值过渡。
- 持续遮挡：保持，不重复创建材质。
- 刚解除遮挡：使用短延迟／不同退出阈值后恢复，避免反复闪烁。
- 对象 EndPlay：从集合清理，不能留下无效引用或访问已卸载组件。

### 9.3 材质方案

首选为参与墙体的统一遮挡材质函数，暴露 `Cutaway` 和切孔位置／半径等参数。局部切孔通常比整段墙完全消失更能保留建筑轮廓；狭窄的特定墙段也可配置整段隐藏。

- Masked 材质通过 `Opacity Mask` 控制像素是否绘制，不使用 Translucent 的 `Opacity` 连续透明概念。
- 参数驱动的是 Mask 输入／材质函数，不是每帧改变 Blend Mode 或 Opacity Mask Clip Value。
- 渐隐可以评估 DitherTemporalAA／抖动遮罩，但必须测实际抗锯齿与运动下的噪点、拖影；它不是无条件平滑透明。
- 大面积 Translucent 墙体可能引入排序、叠层、深度和阴影表现问题，不作为默认方案。

参数按组件隔离：可用缓存好的 DMI 或 Custom Primitive Data；不能改共享原始材质资产，导致所有房间的同一墙材质一起消失。ISM／HISM 的单实例差异需用 Per Instance Custom Data 或按房间分组；一个跨所有房间的实例组不能只靠组件级参数实现每间房独立显隐。

房间可见性与墙体切除由一个最终规则合成。概念上正常细节的可见权重为：

```text
DetailVisibility = RoomReveal * (1 - WallCutawayAtPixel)
```

黑场代理另走自己的权重与切除规则。不能让 Occluder 在恢复墙材质时把隐藏房间顺便恢复为正常显示。实际使用二值 Mask、组件隐藏或抖动过渡时，以上公式只是职责说明，不是直接套在所有 Mesh 上的同一材质表达式。

### 9.4 墙体拆分要求

墙面最好按房间边界、门洞与可切除片段拆分。整栋楼一个 Mesh 的情况下，第一版需要作者指定切孔函数或分段资产，不能简单隐藏整个建筑 Actor。

墙体有厚度时，切除可能露出空腔／背面；要决定是否需要封边／剖面材质。Two Sided 本身不能自动补齐被切开的实体截面。

## 10. 交互、扫描与提示不能泄露隐藏房间

房间显示首先是视觉规则。若需要限制玩家对黑场房间的交互，应有明确的业务查询，不要让材质 alpha 成为 CanInteract 的唯一依据。

建议 Region 服务提供类似 `IsTargetInAllowedInteractionSpace(Interactor, Target)` 的只读策略：

- 普通交互目标同时检查物理可达／门的状态与允许交互区域。
- Prompt 和真正执行必须使用相同条件。
- NearbyPickup 列表也要接入相同空间条件，避免在走廊拾取隔墙房间的道具。
- 显隐切换当帧使已有 Prompt／交互查询缓存失效，防止仍沿用本帧早先选中的隐藏目标。
- 通知扫描候选与 Hover 刷新；禁止区域的高亮、信息窗、悬浮提示要清理。

不能把它粗暴实现成“看不见就绝对不能扫描”：扫描本身可能被设计为透视能力。第一版要区分 **普通前景墙被切除** 与 **当前规则禁止展示的其他房间**。后者默认不泄露；若后续允许扫描看隔壁，采用明确策略覆写，不依赖残留 CustomDepth 意外实现。

门口进入预览的视觉阈值与可交互阈值也可以不同。显示房间并不允许玩家越过关闭门交互家具。

## 11. 离家与医院过门的具体顺序

### 11.1 初次离家

```text
住宅正常，楼道提前就绪
  -> 靠近门口：允许过渡构图所需的楼道部分
  -> 开门／跨门演出：短暂允许两侧所需视觉
  -> 玩家跨入楼道：住宅细节渐黑，楼道 Profile 接管
  -> 关门完成且脚下安全：卸载住宅内部
  -> 保留楼道拥有的门体、门框与住宅方向黑场封口
```

在门口过渡期间，两侧显示是一项受控例外，不是永久开放整套住宅。角色通过判定平面但模型仍在门框中时，不要马上隐藏相交的一半角色或卸载脚下地面。

家门、门外锁门 QTE、关门镜头所需结构归楼道／入口关卡；室内家具和房间体积归 Home。跨 Level 硬引用应尽量避免，使用稳定 ID／注册，卸载后弱引用失效不影响门外逻辑。

“永久卸载”指本次叙事流程不再加载旧住宅。新游戏或读取离家前存档仍允许加载 Home；这不是删除关卡文件。

### 11.2 追逐返回

返程只保留楼道视图和住宅方向黑场，不加载旧住宅内部。开门进入医院时由过门事务准备医院、切换 Profile／可见集合并对齐视图。关门瞬间切断怪物声与追逐音乐，医院场景稳定后再卸载旧入口／室外。

黑场服务不能擅自提前显示医院；医院是否准备、何时跨门、何时提交章节状态属于剧情／流送事务。

### 11.3 与室外版本流送的关系

已经讨论的空间组织为：住宅、楼道入口、单元楼道外至水池台阶前的完整室外区、台阶／广场、医院入口。

完整室外区计划有去程、追逐和终章备用三个版本；它们是互斥活动版本，备用版不参加序章运行。版本切换期间 View 使用独立稳定的广场安全区；新区域注册完成后才解析其视觉组件，旧区域注销时清理切除状态。本文不要求接手者现在复制或改造这些地图。

## 12. 生命周期、优先级与时间

### 12.1 临时镜头覆盖

QTE、过场、追逐镜头、死亡与地区 Profile 可能同时存在。镜头服务应使用有 Owner／Handle 的临时覆盖请求，释放自己的请求后恢复当前仍有效的空间配置，避免保存一份旧 Profile 后硬写回已经离开的房间。

建议语义优先级：死亡／强制过门 > 明确的过场镜头 > QTE 特写 > 普通区域镜头。实际数值集中定义，镜头优先级不直接复用输入优先级数字。视图覆盖不能替代输入仲裁。

Director 的 EndPlay、QTE 取消、玩家死亡、Pawn 替换和 View Owner 丢失都必须释放相应请求。

### 12.2 扫描冻结与 Pause

- 扫描冻结下，维持现有相机是否允许 Look 的规则；空间系统不能为了更新相机额外授予 Look 权限。
- 镜头构图／遮挡表现不能依赖被角色 Freeze 缩放到 0 的 Character Delta。
- 继承既有 SpringArm 的冻结例外。需要独立时钟时先使用现有 TimeSubsystem，明确“忽略 Freeze、Pause 时停止”的契约，不新建 FPlatformTime 时钟。
- Pause／设置菜单覆盖期间不累计一大段过渡时间；恢复后不能瞬间补算几秒 Fade。
- 暂停时不推进普通房间动画，但如果读档／传送使位置发生实质变化，恢复前仍必须重建正确空间，不能露出旧房间。

### 12.3 复活、传送与重新加载

在复活目的地区域真正就绪后：

```text
传送角色并同步必要朝向
  -> 清理旧 Portal／Room 候选与旧墙体切除集合
  -> 立即解析新 Room 和合法视图
  -> 初始化新 Profile，不从旧房间长距离插值
  -> SkipLagOnce / 既有 ResetCameraForRespawn
  -> ResetAutoFocus
  -> 当前空间视觉就绪后恢复画面与输入
```

具体合并进现有复活流程时遵守 [HealthAndRespawn.md](HealthAndRespawn.md)；不能把上述步骤另起一个第二复活系统。

区域注销时恢复／释放自己修改的材质参数、可见性和阴影状态，移除弱引用。若一个共享组件仍被其他有效区域使用，按最终状态重算，不直接无条件恢复可见。

初始材质槽、组件可见性、阴影设置及自定义参数应有可恢复记录；不能结束功能时把所有对象统一强制设为 Visible=True。

### 12.4 存档边界

当前 RoomId、渐隐进度、墙体切除对象列表、相机偏移和运行时 Handle 都是可推导视图状态，第一版不写存档。

继续由既有剧情阶段、目的地区域与检查点恢复世界，再根据玩家位置重建视图。若以后需要跨门中途存档，必须先定义事务恢复规则；不能把某一帧的半黑、半加载状态直接序列化。

## 13. 参数与 Blueprint 制作约定

建议的 Content 组织，仅为未来目录约定：

```text
Content/Camera/RoomView/Profiles/
Content/Camera/RoomView/Materials/
Content/Blueprints/RoomView/
```

建议的 Profile：Bedroom、HomeHall、LivingDining、EntranceCorridor、Outdoor、Chase、HospitalEntry。小房间之间先共用 Profile，必要时实例级覆盖，不一开始为每一面墙建独立资产。

设计师每个房间需要提供：

1. 角色 Region 体积，不能有覆盖整栋楼的意外大范围。
2. 连接门洞与 Portal 朝向。
3. 当前房间要显示的细节组件；共享墙、地板归属明确。
4. 黑场代理的 footprint、剖切轮廓与边界。
5. 可切除墙段，以及永不切除的门／地板等排除项。
6. 相机观察中心边界或安全锚点，区别于角色 Region。
7. Profile 选择与必要的局部不对称偏移限制。

第一版用显式组件列表／注册保证正确，再考虑从附着层级批量收集。不能依赖运行时解析 Outliner 文件夹作为唯一归属依据；临时 Actor 名、Floor_数字和编辑器 RefPath 都不能作稳定 RoomId。

## 14. 性能与资源处理

- 不每帧遍历世界，也不每帧创建 DMI、动态材质或临时数组大集合。
- Region／Portal 用进入退出事件维护候选，并在初始化与传送时主动重建。
- 候选墙可空间缓存；实际切除效果仍要对最终相机移动及时响应，不能简单降到很低频率造成镜头先穿墙、几帧后才隐藏。
- 只更新变化的视觉状态与材质值；完全显示／完全黑场稳定后停止无意义插值。
- 隐藏不等于卸载。需要单独测主渲染、阴影、CustomDepth、灯光与粒子成本。
- 不因房间黑场就执行全局 GC 或卸载共享资源；大资源释放仍归关卡流送。
- 材质按组件或实例隔离，避免一个共用材质参数改动导致整个小区都消失。
- 第一版不做复杂房间图遍历、全场景屏幕空间门户渲染或全局自定义渲染器。先完成一个可信的走廊＋卧室样例。

## 15. 推荐实施阶段

### 阶段 A：动态镜头配置

先实现 Profile、区域判定和单一镜头参数写入路径。用一个测试区验证距离、偏移、过渡与旧地图 fallback；保留现有输入设置和冻结行为。

### 阶段 B：房间黑场

加入当前房间／门口预览／非当前房间三种策略，以及黑场代理。先做到走廊里姐姐房间黑、到门口显示；不做全住宅流送，不删除房间 Actor。

### 阶段 C：墙体切除

指定少量墙段接遮挡材质，加入最终视图检测、切除与恢复。验证关闭 Boom collision test 的情况下，角色仍清楚可见且碰撞不变。

### 阶段 D：边界防探看与其他系统

完成楼道不对称偏移／最终安全视图、扫描高亮和交互过滤、Prompt 缓存刷新、QTE／过场覆盖及复活重置。

### 阶段 E：离家／医院与正式资源推广

接入 Home 卸载和入口黑场封口；接入医院过门事务。确认材质与空间规则后再推广到父母房、妹妹房等，不直接一次改动所有正式地图。

建议新增 C++ 文件位于 `Source/The_Awakening/Camera/` 或项目统一的 SceneView 目录；保持现有组件名和 Blueprint 引用兼容。自动化测试按项目惯例放 `Tests/`。所有文件名最终由实施者与项目结构统一，本文不要求机械照抄名字。

## 16. 验收清单

### 16.1 自动化／逻辑测试

- 相同优先级 Region 重叠时选择稳定；无 Region 能 fallback。
- Portal 有限门洞范围、有向穿越与两侧缓冲，不在门槛抖动。
- 只移动相机不改变 ActiveRoom，也不解锁房间预览。
- Profile 大范围切小范围时偏移不越界，数值有限，无非法负距离。
- 临时镜头覆盖结束后恢复当前位置的 Profile，Owner 销毁时不遗留请求。
- 非当前房间恢复墙体切除时仍保持黑场。
- 共享墙与共享组件不会被两个区域互相覆盖。
- 传送、注册延迟、子关卡注销、Pawn 更换后无旧对象访问。
- 缺材质／缺代理／缺 Profile 给出可诊断 fallback，不让玩家全屏黑且无法操作。
- 房间改变同时使交互／Prompt／扫描缓存失效。

### 16.2 必须实际 PIE 的画面与操作

| 场景 | 预期 |
|---|---|
| 住宅连接走廊来回走 | 当前走廊可读，姐姐房间黑，无闪烁 |
| 姐姐房门口前进／后退／侧移 | 只在合法门口范围显现，退出后恢复黑场 |
| 爸妈房看向妹妹房 | 妹妹房不因镜头探看显示 |
| 鼠标／RS 推到四个极限 | 无穿模、镜头进墙或相邻房间泄露 |
| 墙角、门框附近快速移动 | 不漏掉上半身遮挡，墙不会频繁闪回 |
| 切墙后尝试穿过去 | 角色仍被物理墙挡住 |
| 家门跨越并关门 | 两侧过渡自然，关门后住宅可卸载且左侧仍黑 |
| 公寓楼道向住宅方向探看 | 不出现家具、模型背面或天空 |
| 扫描时移动观察、开关背包／暂停 | 输入权限、冻结例外、高亮与黑场正确 |
| QTE 中切镜头、失败、死亡 | 请求正常释放，复活不从旧镜头飞来 |
| 房间内文档／日记预览 | 预览台与 UI 不受世界黑场污染 |
| 不同分辨率／宽高比与抗锯齿设置 | 门边不露景，切孔不过小，抖动渐隐可接受 |

### 16.3 回归和交付说明

后续实现时按实际修改选择现有 Camera.AutoFocus、Input、Freeze／Time、Prompt／Interaction、Document／Preview、Respawn 相关测试；不能只测新组件。不要把单点 Trace 成功说成完整通行验收。

交付应明确列出：已实现字段与 Blueprint 接线、使用了哪些测试关卡、哪些正式房间已配置、材质支持范围、未覆盖的视角／平台、PIE 与打包实际结果。**本规划文档不代表这些功能已经通过测试。**

## 17. 建议调试可视化

开发时建议在可关闭的调试模式显示以下信息；命令名称待实现，不是当前已有命令：

- ActiveRoom、预览 Room、当前 Portal 与 Priority。
- 当前／目标 Camera Profile、Boom 长度、允许偏移范围。
- 原始 Look 意图、约束前／后偏移、最终镜头位置。
- Room Volume、Portal 门洞法线、观察中心边界、相机安全锚点。
- 正在切除／等待恢复的组件及原因。
- 当前主要镜头覆盖 Owner、过渡运行版本号。

遮挡射线、边界框和文字不能默认进入正式包画面。不要使用永久 Tick PrintString 作为实现的一部分。

## 18. 接手实现前应确认的事项

这部分应通过检查项目和制作最小样例解决，不要求先凭空设计完整系统：

1. 检查实际 Character BP、Boom／相机变换和 DoLook 覆盖，确认世界轴与屏幕轴映射。
2. 画出连接走廊、姐姐房门口与房间的三个区域，确认客厅／餐厅是否作为开放空间。
3. 确认参与样例的墙体是否分段、使用什么材质，怎样在不影响其他墙的情况下驱动参数。
4. 确认扫描正在使用的 CustomDepth／Stencil 范围，避免黑场增强方案冲突。
5. 决定黑场代理用剖切轮廓还是后处理辅助；先用当前灯光／雾实测，再推广。
6. 先证明门口显示、墙体切除和镜头限位组合后不会相互覆盖，再加入流送卸载。
