# 房间视图与镜头：剩余工作

更新时间：2026-11-03。

本文只记录当前框架下尚待完成或验收的工作。现有系统的使用和配置见 [RoomViewHandover.md](RoomViewHandover.md)，具体行为以当前源码为准。

已完成的区域镜头、显式黑场规则、交互／拾取／扫描候选过滤和复活镜头重置不再作为计划项保留。旧 Region／Portal 设计、门口自动预览、邻接房间可见集合，以及切除盒子、世界空间切孔材质和 MPC 方案均已从本规划移除。

## 1. 楼道镜头防探看

四向不对称观察限位已经支持。后续先用现有 Profile 调整楼道向住宅方向的限位，再补齐当前尚无的最终输出视图安全约束。

- 观察限位填 0 可以禁止向指定方向继续偏移，但不能单独保证 Camera Lag、区域混合和相机附加偏移后的最终视图始终安全。
- 安全范围应单独定义，不能要求固定侧视镜头必须位于角色所在房间的体积内。
- 如果需要修正最终视图，应在 `UTAAutoFocusCameraComponent::GetCameraView` 获取实际视图之后、计算自动对焦之前完成，确保对焦使用修正后的 `DesiredView`。
- 保持 Camera Boom 的 collision test 关闭，不用整根 Boom 自动回缩替代构图约束。
- 无法满足安全范围时应有明确的安全构图，避免在门边或墙角反复跳动。

主要入口：[TARoomViewComponent.cpp](../Source/The_Awakening/Camera/TARoomViewComponent.cpp)、[TAAutoFocusCameraComponent.cpp](../Source/The_Awakening/Camera/TAAutoFocusCameraComponent.cpp)。

## 2. QTE、过场与追逐镜头覆盖

当前房间镜头组件尚无带 Owner／Handle 的临时覆盖接口。需要特殊镜头时，在现有镜头参数求解路径中扩展，不另起一套每帧写 Boom 的逻辑。

- 覆盖请求需明确优先级、持有者与释放条件；建议死亡／强制过门高于过场，过场高于 QTE，普通区域镜头作为基础配置。
- 请求结束时重新取当前位置的有效配置，不能把开始演出时保存的旧房间参数直接写回。
- QTE 取消、Director EndPlay、死亡、Pawn 更换及持有者失效时释放请求。
- 沿用现有输入仲裁与时间系统；镜头覆盖不自行授予 Look 权限。扫描冻结下继续遵守镜头的 FreezeExempt 行为，暂停时不累计过渡时间。
- 保留现有 `SnapToCurrentLocation` 与复活重置接线，新增覆盖后只补充请求清理和恢复验证。

## 3. 黑场与其他表现的剩余边界

交互提示与执行、NearbyPickup、扫描候选已经接入 `UTARoomRegistrySubsystem::IsActorInBlackoutRoom`，不再规划第二套房间过滤服务。剩余问题按现有实现补齐和验证：

**重点待修复：黑场切换时正在扫描／交互／拾取的场景，目前存在 Stencil／Post Process 绘制问题，尚未通过验收。应先修复绘制问题，再进行该场景的完整验收。**

- 排查 CustomDepth／Stencil 写入、恢复与黑场后处理绘制之间的关系；扫描可能改写黑场组件的 Stencil，需检查黑场值 3 是否被高亮覆盖。具体原因尚待定位，不能将候选过滤已接入视为绘制问题已解决。
- 扫描目标是在刷新候选时排除的；检查切换当帧的既有高亮、Hover 和信息窗是否及时清理。若出现残留，再补相应刷新。
- 空间过滤使用 Actor 原点；跨房间的大物件、门口重叠区域和未登记物品需实测，不能把它视为逐组件几何判断。
- 灯光、粒子、Decal 等没有随房间黑场统一处理。按正式场景需要补充配置，视觉处理不能顺带停止剧情声音、Tick 或剧情状态。
- 当前黑场为瞬时切换。是否需要过渡应以实际画面需求决定，不把旧的 RoomReveal／代理权重方案直接接回当前系统。

当前黑场由 WorldSubsystem 统一管理。若以后增加多个本地玩家或独立游戏视图，需要另外评估视图隔离；现有结构不代表已支持每个视图独立黑场。

## 4. 离家卸载与医院过门

按当前交接记录，住宅仍在 `Persistent_Level` 中。正式流送前先核对并整理关卡归属，再接入既有剧情、存档和复活流程。

### 初次离家

1. 把住宅内部拆为可卸载子关卡；楼道入口保持独立可用。
2. 家门、门框、门外锁门 QTE、必要地面及住宅方向黑场封口归入口一侧，卸载住宅后仍能工作。
3. 在开门／跨门演出前准备好楼道，使用当前显式黑场规则配置过渡所需画面，不恢复 Portal 预览逻辑。
4. 玩家完全离开门框、关门完成且脚下安全后，再卸载住宅内部。
5. 卸载后检查区域注销、渲染状态清理及入口引用，避免访问已卸载对象。

本次序章离家后不再返回旧住宅；新游戏和读取离家前存档仍需能加载住宅。这是运行流程约定，不是删除住宅资产。

### 追逐返回与医院

- 返程不加载旧住宅内部，入口保留住宅方向的黑场封口。
- 医院门后先用占位平台验证目的地准备、传送和镜头切换，再接正式资源。
- 医院是否就绪、何时跨门及何时提交章节状态由剧情／流送流程决定，黑场逻辑不代替这些判断。
- 关门时按剧情要求切断怪物声和追逐音乐；医院稳定后再卸载旧入口／室外。
- 目的地区域就绪后复用现有镜头重置入口；不能从旧场景长距离插值，也不能新建第二套复活或存档系统。

室外去程、追逐与备用版本的组织属于后续流送工作；本文不要求现在复制地图。若实现互斥版本切换，应先保证安全落脚区和新区域就绪，再撤掉旧区域。
